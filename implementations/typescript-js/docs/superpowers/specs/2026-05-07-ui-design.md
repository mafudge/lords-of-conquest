# UI Design (Plan 6)

**Date:** 2026-05-07
**Scope:** Browser UI for *Lords of Conquest* — the human-facing layer over Plans 1-5 (engine + AI). Single plan, ~70 tasks.

## 1. Goals

- Deliver a playable game from setup to gameOver, supporting 2-7 players in any mix of human and AI personas.
- Honor the original spec's "modern flat aesthetic, single fluid screen plus context-sensitive overlays."
- Animate every AI move (boats slide, items pulse, combat flashes) so the watching human can follow what happened.
- Run entirely client-side from a static Vite build.
- Portfolio-credible polish: real browser E2E test, snapshot regression coverage, save/load with named slots.

## 2. Decisions summary

| Topic | Decision |
|---|---|
| Scope | Single Plan 6 (~70 tasks) |
| Form factor | Desktop-first, responsive down to tablet (≥768px) |
| Layout | Top bar + bottom bar with board centered |
| AI pacing | Full animated moves with skip-via-Space |
| Interaction pattern | Inline board picking (glowing candidates) for tile-targeted actions; modal/expanded-bar for non-tile flows |
| Setup wizard | Two-pane (form left, live preview right) |
| Persistence | localStorage autosave + 3 named slots; map text save/load; URL `?seed=` reads at app start |
| Scouting Report | Right-side drawer with 4 tabs (Force Count, Stockpiles, Save Map, Boat Info) |
| Testing | Vitest + happy-dom for render/snapshot/interaction units; 2 Playwright E2E smoke tests |
| Animation | Web Animations API + CSS transitions, no library |
| Framework | Plain DOM + CSS Grid + SVG glyphs — no React, no game framework |

## 3. Architecture

**Pattern:** Vanilla MVU.

```
let state: GameState = …;
function dispatch(plan: Plan): void {
  const prev = state;
  state = reduce(state, plan);
  scheduleRender(prev, state);    // diff prev → state for animations
  scheduleAutosave();              // debounced 500ms
}
```

`scheduleRender` uses `requestAnimationFrame` to coalesce multiple dispatches in the same frame. `render(state, prev?)` mounts/updates DOM. Render is idempotent — calling twice with the same `state` produces no DOM diff.

**AI tick loop** lives in `runtime.ts`. While `state.players[state.currentPlayer].persona !== 'human'` and the game is not over and there's no pending human input, the loop:
1. Computes the next AI plan via `decideAction(state, currentPlayer)` (or `decideTradeAction`, `decideAlliesAction`, etc. for pending interrupts).
2. Awaits `animatePlan(prev, next, plan)` from `animations.ts`.
3. Calls `dispatch(plan)`.
4. Yields to the event loop, then repeats.

The skip key sets `fastForward = true`; animations honor this by resolving instantly. Human input always pauses the loop — the runtime checks `state.players[state.currentPlayer].persona === 'human'` between ticks.

**Boundaries:**
- `src/ui/` is the only browser-DOM consumer.
- `src/ui/` imports `src/game/*` (engine + AI) and `src/platform/*` (urlSeed, mapTextCodec, storage).
- `src/game/*` and `src/platform/*` MUST NOT import from `src/ui/*`.
- All animation/pacing belongs to `src/ui/`. The engine remains synchronous and frame-agnostic.

## 4. Visual layout

### 4.1 Top bar (52px fixed)

- **Left (240px):** year badge `Year 3`, phase label `Trade`, player turn-order strip — mini circle avatars in turn order with the active one ringed in their color and 110% scale.
- **Center (flex):** `<div class="status-banner">`. Empty during human turns. During AI turns shows `Blue is proposing a trade to Cyan…`, etc. Hidden when `state.currentPlayer === human` and `pendingTrade?.tradeeId !== human`.
- **Right (200px):** `Scouting Report` button (toggles right drawer); gear icon (opens menu: New Game, Save Slot N, Load Slot N).

### 4.2 Board (centerflex, fills available)

- 40×20 SVG `<g>` elements. Each square is a `<rect>` with width/height = computed from viewport (32px @ 1280px viewport, 22px @ 768px tablet).
- Land squares: `fill = playerColor[ownerId]` at 40% saturation. Water: `#1c2740`.
- Territory boundaries: 2px stroke between adjacent squares of different ownership, drawn as a separate `<path>` overlay.
- Glyphs (city, weapon, horse, stockpile): inline SVG rendered at the territory's centroid square. City = stylized building, weapon = sword, horse = horse silhouette, stockpile = crate.
- Boats: `<g class="boat">` translated to `(boat.x * cell, boat.y * cell)`. Embarked horse/weapon shown as small adjacent glyphs.
- Force-count badges: top-right of centroid square. Off by default; toggled on by a switch in the Scouting Report drawer (`Always show force counts`).
- During an active interaction mode, candidate tiles glow via CSS `box-shadow: 0 0 0 3px var(--player-color); animation: pulse 1.2s infinite`.
- Click on board routed to active interaction mode handler (one mode at a time).

### 4.3 Bottom bar (88px default, expands to 160px for trade/build)

- **Left (flex):** stockpile pill list. One per active player. Pill markup:
  ```html
  <div class="pill" data-player="0" data-active>
    <span class="swatch" style="background: var(--p0)"></span>
    <span class="name">Red</span>
    <span class="r">I 3 · C 2 · T 1 · G 0 · H 1</span>
  </div>
  ```
  Active player's pill has a 2px ring of their color and a subtle glow.
- **Right (auto):** phase action buttons. Set varies per phase:
  - Selection: `Auto-pick`, `Skip Animations`
  - Trade: `Propose Trade ▾`, `Reject All from <player>`, `Finished Trading`
  - Shipment: `Move Stockpile`, `Ship Horse`, `Ship Weapon`, `Move Boat`, `Skip Shipment`
  - Conquest: `End Conquest` (the attack flow runs in interaction mode + a small side panel)
  - Development: `Build City`, `Build Weapon`, `Build Boat`, `End Development`
- **Expanded mode:** when a non-tile interaction is active (trade builder, build menu), the bar grows to 160px and shows the editor inline.

### 4.4 Right drawer (Scouting Report, 320px, slide-in)

See §10.

### 4.5 Color palette

- 7 player colors (engine palette): red, blue, cyan, purple, orange, green, yellow. Defined as CSS custom properties `--p0` through `--p6`.
- Background slate `#1f242e`. Mid panels `#2a2f3a`. Borders `#3d4250`.
- Text primary `#e4e7ed`, muted `#9ba3b3`.
- Accent (primary buttons) `#3a8a4f`. Destructive `#a14250`.

## 5. Setup wizard

Two-pane modal that mounts at app start (or when the user picks "New Game"). Wizard state held in a local `let setupState: SetupState`; on `Start Game`, dispatches `{ kind: 'newGame', setup, seed }` and unmounts.

### 5.1 Left pane (form, 480px wide)

Six sections (collapsible, all expanded by default):

1. **Players** — list of slots, 2-7. Per slot: color swatch picker (cycles through unused colors), name input, persona dropdown (`Human / Passive / Defensive / Aggressive`). Add/remove rows. Drag-handle to reorder.
2. **Rules** — cities to win (3-8 stepper, default 5), Element of Chance radio (Low/Medium/High, default High), randomize player order toggle (default on).
3. **Map options** — water boundary toggle, water area radio (small/medium/large), territory count stepper (8/12/16/20/24/32/40/48/56/64, default 24), islands radio (none/some/lots, default some), shapes radio (regular/irregular).
4. **Resources** — mode radio (fixed/random) × density radio (very low / low / medium / high). 8 combinations. Default: fixed/medium.
5. **Save/Load map text** — two buttons opening textarea modals. Used to share specific maps.
6. **Footer** — `Start Game` (primary, accent green; disabled until ≥2 players + map generated). `Reset to defaults` (secondary).

### 5.2 Right pane (live preview, fills remainder)

- Reuses `board.ts` renderer scaled to fit the pane.
- Above preview: `Re-roll seed` button + seed value display (`seed: abc123`).
- Below: small map metadata (`24 territories · 12 land · 4 lakes`).
- Auto-regenerates 200ms after any map-options field change. Player/rules edits do NOT regenerate.

### 5.3 Persistence

- `localStorage['loc:setup:last']` stores the most recent `setupState` (player config + map options) — re-opening the app prefills the wizard.
- URL `?seed=abc123` (parsed by `src/platform/urlSeed.ts`) overrides the seed on first load.

## 6. Per-phase UI behavior

### 6.1 Selection (one-time)

- Phase entered after `endPhase` from setup-equivalent transition.
- Board enters `selectionMode`.
- All unowned territories glow in current player's color.
- Top bar: `Selection · Round 2 · Red turn`.
- Bottom bar: `Auto-pick` button (uses `decideSelectionAction`).
- Click a glowing tile → `dispatch({kind:'selection', player, territoryId})`.
- AI player: ~400ms pause, captured tile flashes + color fade-in.
- Phase ends when no unowned tiles remain. Engine handles transition.

### 6.2 Production (auto, no input)

- Top bar status: `Year 3 · Production`.
- 1/6 skip path: full-screen flavor banner with random `reasons.txt` line, 1.5s fade, then advance.
- Otherwise: per-player resource gains animate as glyph icons flying from each producing tile to the player's stockpile pill (~300ms each, parallelized within a player). Stable territory plays a horse-place animation (or fade-out for "no qualifying neighbor — lost").
- **Locate Stockpile interrupt:** if any player has stockpile but `stockpileLocation === null`, the engine emits a pendingInteraction state. UI handles this:
  - Human: enters `locateStockpileMode`. Owned territories glow. Click → dispatch.
  - AI: heuristic `auto-locate` (highest force-count owned tile), dispatched immediately.
- After all locations resolved, engine advances phase.

### 6.3 Trade

- 1/6 skip → flavor banner.
- 2-player game → fully skipped silently (no UI flash).
- **Human active:**
  - Bottom bar: `Propose Trade ▾`, `Reject All from <player>` (only if there's pending hostility), `Finished Trading`.
  - `Propose Trade` opens tradee picker (popover from button), then opens trade builder modal.
  - **Trade builder modal:** give/receive editors with 5 resource counters per side (+/- buttons). Live summary line. Horse counter — if either side has horse > 0, additional horse-from/horse-to pickers appear; clicking them dims the modal and prompts for territory click.
  - Send → dispatch `{kind:'trade', proposer, tradee, give, receive}`. Engine sets `pendingTrade`. UI animates card flying to tradee's pill.
  - Cancel → modal closes, no dispatch.
- **Human is tradee with pendingTrade:** modal `<TradeResponse>` opens. `Accept` / `Reject` / `Reject All from <proposer>`. Dispatches `{kind:'tradeResponse', accept}` or `{kind:'rejectAll', proposer}`.
- **AI proposes:** banner narrates, card animates. AI tradee → ~400ms pause, accept/reject animation (green check / red x).
- Triple-reject lockout enforced engine-side. UI shows `(rejected 3 times — locked)` next to the tradee in the picker.

### 6.4 Shipment

- 1/6 skip → flavor banner.
- One shipment per player per turn.
- **Human:** bottom bar shows 4 mode buttons + skip. Each opens a sub-mode of `shipmentMode`:
  - `Move Stockpile`: source = current stockpile location (auto), destination = any owned territory.
  - `Ship Horse`: source = any owned tile with a horse; destination = adjacent owned tile (or 2-hop with rest-stop hint).
  - `Ship Weapon`: source = any owned tile with a weapon; destination = adjacent owned tile only.
  - `Move Boat`: source = any owned boat; destination = water cell on same lake. After picking destination, popover offers `Embark horse from…` and `Embark weapon from…` per the rules.
- Source highlight → click source → destinations highlight → click destination → confirm dialog or instant dispatch (depending on whether sub-options apply).
- **AI:** asset slides along path (300ms per hop). 2-hop horse pauses 100ms at rest-stop. Boat slides along water cells with embarked items riding alongside.

### 6.5 Conquest

- Up to 2 attacks per turn. `attackNumber` and `shipmentForfeitsSecondAttack` tracked engine-side.
- **Human:**
  - Board enters `conquestMode`. Adjacent enemy/unowned territories from owned tiles glow as candidates.
  - Click target → side panel slides up over the bottom bar showing `Attacker: 5 · Defender: 3 · Others: Blue 1, Cyan 0`.
  - Below the readout: `Bring Forces ▾` (sub-panel listing eligible non-touching horses/weapons/boats), `Allies` row (auto-prompts for AI third parties; pending humans block until resolved via the alliesDialog overlay), `Attack` button (greyed with `LOSE!` indicator if auto-suicide).
  - Confirm Attack → dispatch `{kind:'attack', ...}`. Engine creates pendingCombat. UI runs allies resolution (if any), then resolveCombat. Animations: target flashes, attacker glyph beams toward target, captured-tile color sweep on win OR attacker tile loses force on loss.
  - End Conquest → dispatch `{kind:'endPhase'}`.
- **AI:** target highlight flashes briefly, attacker glyph beams, combat animates as above. ~700ms per attack.

### 6.6 Development

- **Human:** bottom bar grows to 160px and shows 3 build mode buttons + `End Development`. Each shows resource cost + gold alternative ("1 Iron + 1 Coal + 1 Tree + 1 Gold OR 4 Gold").
- Click a mode → board glows eligible tiles (no city for City; no weapon for Weapon; coastal with at least one available port slot on at least one bordered lake for Boat — engine helper `canBuildBoatAt(state, terrId)` exists from Plan 4).
- Click target → if multi-lake territory + boat, popover prompts for which lake.
- Confirm → dispatch. Resources animate from stockpile pill to tile, glyph appears.
- **AI:** same animations, no popovers (engine-decided).

## 7. Interaction modes

A single active mode at a time (`interactionMode.ts` exports `let active: Mode | null`). Modes:
- `selectionMode` — selection phase
- `shipmentMode.subStockpile / subHorse / subWeapon / subBoat` — shipment phase, set by clicking the bottom-bar sub-mode button
- `conquestMode.target / bringForces / allies` — conquest phase, advances through sub-states
- `developmentMode.city / weapon / boat` — development phase, set by clicking the bottom-bar build button
- `locateStockpileMode` — post-production interrupt

Mode contract: each mode exports `enter(state)`, `handleClick(tileOrBoatId, state)`, `exit()`. The board click handler delegates to `active.handleClick(...)`. Modes are responsible for setting CSS classes on the board (`data-candidate="true"` on glowing tiles) on `enter` and clearing them on `exit`.

## 9. Animation strategy

**Library:** none. Web Animations API (`element.animate(keyframes, options)`) for transforms, CSS transitions for color/opacity.

**Choreography contract:** `animations.ts` exports `animatePlan(prev: GameState, next: GameState, plan: Plan): Promise<void>`. Returns a Promise that resolves when the animation finishes (or instantly if `fastForward` is set).

Per-plan choreographies:

| Plan kind | Animation |
|---|---|
| `selection` | Captured tile color fade-in 200ms |
| `production` | Per producing tile: resource glyph spawn → tween to player pill (300ms, parallelized within player). Stable: horse-place or fade-out |
| `buildCity` / `buildWeapon` / `buildBoat` | Resource icons fly stockpile-pill → target tile (250ms), glyph pop-in (scale 0→1, 150ms) |
| `shipStockpile` | Crate glyph translates source → dest (300ms) |
| `shipHorse` | Horse glyph translates; 2-hop pauses 100ms at rest-stop |
| `shipWeapon` | Weapon glyph translates 1 hop (300ms) |
| `shipBoat` | Boat sprite translates along water cells; embarked items ride alongside |
| `trade` (proposed) | Card sprite flies proposer-pill → tradee-pill (400ms) |
| `tradeResponse` (accept) | Stockpile chips swap between pills (300ms each side) |
| `attack` / `resolveCombat` | Target tile flash red 100ms × 3, then captured-tile color sweep (400ms on win) or attacker red flash (on loss) |
| `endPhase` / `production` skip / `endTurn` | No animation |

**Pacing:** the AI tick loop awaits each animation Promise. No fixed `setTimeout` on top.

**Skip key:** `Space` toggles `fastForward`. Animations honor it by completing instantly (set the keyframe progress to 1).

**Reduced motion:** respect `prefers-reduced-motion: reduce`. Replace tweens with instant state changes; preserve combat color flashes for feedback.

## 10. Persistence

### 10.1 Game-state save/load (localStorage)

- **Autosave:** every `dispatch()` enqueues a 500ms-debounced write to `localStorage['loc:save:autosave']`.
- **Named slots:** `loc:save:slot1` / `loc:save:slot2` / `loc:save:slot3`. Top-bar gear menu has `Save Slot N` (overwrites) and `Load Slot N` (replaces current state — with confirmation if game in progress).
- **Format:**
  ```json
  {
    "schemaVersion": 1,
    "savedAt": "2026-05-07T18:30:00Z",
    "state": { /* GameState */ }
  }
  ```
- **JSON serialization:** `GameState` contains `Set<number>` (e.g. `bordersLakes`, `alliesPending`). `JSON.stringify` doesn't handle `Set`. UI must use a structured-clone-aware serializer or convert Sets to arrays at save time and back to Sets at load time. Implement helper `serializeState` / `deserializeState` in `src/platform/persistence.ts` with explicit Set ↔ Array conversion for the known fields.
- **Schema mismatch on load:** show toast `"Save is from an older version (schema N); cannot load."` Refuses; no migration in MVP.

### 10.2 Map text save/load (matches Gettman)

- Reuses Plan 1's `mapTextCodec`. Save = read; load = paste textarea + parse + replace map.
- Available in setup wizard (pre-game only) and Scouting Report drawer's `Save Map` tab (read-only post-game-start).

### 10.3 URL `?seed=` (read-only at app start)

- Parsed by Plan 1's `urlSeed.ts`.
- If present at app start, prefills setup wizard's seed field and auto-rolls a map preview.
- No UI for sharing — user copies their own URL if they want to share.

- Right-side drawer, 320px wide, slides in/out via top-bar `Scouting Report` button.

- Tabs:

## 12. Testing strategy

### 12.1 Vitest + happy-dom (~30-40 unit/render/snapshot tests)

- **Render functions:** each of `renderShell`, `renderBoard`, `renderTile`, `renderBottomBar`, `renderTradeBuilder`, etc. tested with handcrafted `GameState` fixtures. Assert DOM structure (counts, classes, attribute values).
- **Snapshot tests:** `~5-8 snapshots`. Canonical states:
  - Year 1 selection mid-draft
  - Year 3 trade with `pendingTrade`
  - Year 5 conquest mid-attack with allies pending
  - Year 8 development with full stockpile
  - gameOver
  - setup wizard at default values
- **Interaction modes:** simulate click on a candidate tile in `selectionMode`; assert dispatched plan matches expected. Same for shipment, conquest, development.
- **Persistence helpers:** `serializeState`/`deserializeState` round-trip tests with all `Set` fields populated.
- **Animation skip:** `fastForward = true` resolves all animation Promises immediately.

### 12.2 Playwright (2 E2E smoke tests)

1. **`setup-and-self-play`:** open app → click `Start Game` with default 4-aggressive-AI setup → wait for `gameOver` banner (≤ 60s) → assert winner text matches `Player N (Color) won the game`.
2. **`human-trade-flow`:** open app, configure 1 human + 3 AI, start game → advance through selection (use `Auto-pick`) → reach trade phase → open trade builder → propose `1 Iron for 1 Coal` to Blue → assert AI response (accept/reject card animation) → assert phase advances or new trade allowed.

CI: Vitest on every push; Playwright on PR + main only (separate workflow).

### 12.3 What we don't test

- Visual regressions (snapshot tests cover DOM structure, not pixel rendering).
- Performance benchmarks.
- Cross-browser matrix beyond Playwright's default Chromium.

## 13. Out of scope

- Sound effects.
- Online/networked multiplayer.
- Phone-sized layouts (<768px).
- In-game tutorial / onboarding overlays.
- Theming / palette switcher beyond the default.
- Replay system / move history beyond the visible event log.
- Animation skip-frame controls beyond the binary Space toggle.
- Save state schema migration (mismatch refuses to load).
- Internationalization (English only).

## 14. Implementation notes

- **No new dependencies in MVP except dev deps:** `vite`, `@vitejs/plugin-typescript` (or default), `happy-dom`, `@playwright/test`.
- **Vite entry:** `src/ui/index.html` imports `main.ts`. Vite serves on `npm run dev`; build outputs static assets to `dist/`.
- **Static deploy target:** GitHub Pages from `dist/`. Base path configured via Vite's `base` option to match repo path.
- **Bundle budget:** target <200KB gzipped JS. Plain DOM + no React keeps this trivial.
- **Accessibility:** ESC closes modals; Tab cycles through interactive elements; ARIA labels on board tiles (`aria-label="Territory T17, owned by Red, has city"`); `prefers-reduced-motion` honored; focus rings preserved (no `outline: none`).

## 15. Build order

The plan should land tasks roughly in this order so each task produces a visible result:

1. App shell (HTML, top/bottom bar mounts, theme CSS, palette).
2. Board renderer (`board.ts` + `tile.ts` + `boat.ts`) using static fixture state.
3. State + dispatch + render loop (`main.ts`).
4. Setup wizard (two-pane, with live preview reusing the board renderer).
5. Selection phase end-to-end (interaction mode + animation).
6. Production phase + locate-stockpile.
7. Trade phase: propose, response, builder modal, autoReject.
8. Shipment phase: 4 sub-modes.
9. Conquest phase: target → bring forces → allies → attack → resolve.
10. Development phase: 3 build modes.
11. Animation choreographies (per plan kind).
12. Persistence: autosave + slots + map text.
13. Scouting Report drawer + 4 tabs.
14. AI runtime tick loop with skip key.
15. Tests: Vitest unit + snapshot + interaction; Playwright E2E.
16. Polish: keyboard shortcuts, reduced-motion, ARIA labels, final pass.

The implementation plan will break each into bite-sized TDD tasks.
